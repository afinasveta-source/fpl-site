Этот файл читают ИИ-разработчики (Codex, Claude). Прочитай его целиком перед любой задачей.

Время в интерфейсе и в разговорах — московское (МСК, UTC+3); в базе всё хранится в UTC (`timestamptz`).

## 1. Что это за проект

**Face Painting League (FPL)** — онлайн-лига аквагримёров (бренд MAGFACE, организатор — ИП Афиногенова С. О.).
- **Сезон** → несколько **Игр** (Игра 01, 02 …) → у Игры 3–5 **туров** (последний — финал).
- В каждом туре участницы получают задание, рисуют и сдают фото работы до срока; работы судят судьи.
- **Лиги**: Gold, Silver, Bronze (в Игре 01 — только Gold и Silver; в старых текстах «Лига А» = Gold, «Лига Б» = Silver).
- **Статус участия**: в конкурсе / вне конкурса (рисует для диплома, места не получает) / выбыла / вышла / дисквалифицирована.
  Не сдала в срок → с открытия следующего тура переходит вне конкурса. Не прошла отбор тура → вне конкурса.
- **Судейство**: парные сравнения (судья выбирает лучшую из двух) → балл Брэдли–Терри 1–100 (`bt_100_v1`)
  или оценки по критериям с весами. Переголосование на границе прохода, решение организатора при равенстве.
- **TOP WORK** — лучшие работы тура в каждой лиге: `min(10, floor(20 % работ лиги))`, равные на границе — все,
  меньше 5 работ — нет. В подписи всегда с лигой: «TOP WORK Gold».
- **Итог Игры**: 40 % путь (туры до финала) + 60 % финал. Места 1–3 в каждой лиге, TOP-10/TOP-25 Игры.
- **Очки FPL** (история достижений, НЕ влияют на рейтинг): одно лучшее достижение за Игру
  (Gold 20/15/12, Silver 12/10/8, Bronze 8/6/5, TOP-10 8, TOP-25 5, завершение 3) + 1 за каждый TOP WORK.
- **FPL Rating** — отдельно от очков, парный Elo по сравнениям судей; калибровка 3 тура. Во время Игры на публичном
  сайте рейтинг «заморожен» на начало Игры (Правила, п. 7.3: публичных баллов, мест и общего рейтинга по ходу Игры нет).
- **Диплом** — всем, кто сдал все работы до конца Игры (даже после срока). Номер `FPL-S{сезон}-{игра 2 цифры}-{G|S|B}-{4 цифры}`.
- **Тур-эстафета**: первая лига сдаёт, её лучшие N работ (после судейства) раздаются второй лиге как исходники;
  организатор проверяет раздачу и жмёт «Отправить исходники».

Игра 01 (30.09–10.11.2026) началась в чат-боте SaleBot; бот упал 11.10, туры 1–2 перенесены в кабинет из таблицы
(«Перенос из бота»), с тура 3 Игра идёт в кабинете. Данные бота частично потеряны — не пытайся «восстановить» их сам.

## 2. Из чего состоит система

```
facepaintingleague.com (сервер Selectel, Ubuntu, nginx, PostgreSQL)
├─ /            публичный сайт — статические файлы из dist/ этого репозитория (EN в корне, RU в /ru/)
├─ /data/*.json живые данные для сайта (рейтинг, Игры, TOP WORK) — сервер выгружает из базы раз в 10 минут
│                через функции server/db/site_views.sql (только то, что можно публиковать)
├─ /kabinet/    личные кабинеты (FastAPI, служба fpl-kabinet на 127.0.0.1:8100) — папка kabinet/
├─ /api/        приёмник данных (server/fpl-ingest.py, 127.0.0.1:8081): наборы из бота, закрытые страницы настроек
└─ /admin/*.html закрытые страницы для ввода секретов (почта, копии, мессенджеры) — секрет вводит Светлана сама
```

**Как изменения попадают на сервер — два разных канала:**
1. **Публичный сайт** — сервер раз в 5 минут смотрит последний коммит `main` на GitHub и выкладывает `dist/`.
   ⇒ **Любой push в `main` с изменённым `dist/` сразу публикуется.** Поэтому в `main` напрямую не пушить.
2. **Кабинет, база, скрипты сервера** — только пакетом `out/fpl-ops.tgz` (`bash server/ops/pack.sh`).
   Светлана сама загружает его в хранилище Selectel (бакет `facepaintingleague-site`), сервер применяет его
   cron-ом в течение 5 минут (`server/ops/apply.sh`: миграции базы, код кабинета, перезапуск служб).
   Доступа к серверу (SSH, root) у тебя нет и не будет — это решение владельца.

## 3. Карта репозитория

| Путь | Что там |
|---|---|
| `src/` | исходные страницы сайта (RU), `src/assets/` — общий CSS, `fpl-data.js` (живые данные), шрифты; `src/admin/` — закрытые страницы ввода секретов |
| `build/` | сборка сайта: `bash build/build.sh` → `dist/` (RU → EN `build/i18n/`, SEO, ссылки). Нужен `python3` + `beautifulsoup4` |
| `dist/` | готовый сайт — **генерируется**, руками не править; коммитится вместе с изменениями `src/` |
| `tests/` | `site-check.js` (Playwright по сайту), `check-build.sh` — проверка сборки перед push |
| `kabinet/kabinet/` | backend кабинета (FastAPI + psycopg3, без ORM) и фронтенд `static/assets/*.js|css` |
| `kabinet/tests/` | pytest (≈220 тестов), `demo_server.py` — локальный кабинет с выдуманными данными для скриншотов |
| `kabinet/sim/` | симуляции целых Игр с независимым пересчётом (`oracle.py`), нагрузка; см. `kabinet/sim/README.md` |
| `kabinet/FEED.md` | лента данных `/kabinet/api/feed/*` (только чтение, по ключу) — для автопостинга работ |
| `server/db/schema/NNN_*.sql` | схема базы, миграции по порядку (001…013). Общая база сайта и кабинета |
| `server/db/site_views.sql` | что уходит на публичный сайт (функции `site_export_*`) — фильтр приватности |
| `server/db/fpl-db-setup` | применяет миграции по цепочке (каждую новую нужно вписать в цепочку!) |
| `server/kabinet/` | установка кабинета на сервере (`fpl-kabinet-setup`), копии фото, почта/мессенджеры (`fpl-kabinet-mail`) |
| `server/ops/` | канал обновлений: `apply.sh`, `pack.sh`, `fpl-sync` |
| `server/fpl-ingest.py` | приёмник данных и закрытые настройки (`/api/settings/*`) |
| `server/salebot/` | наследие бота SaleBot (выводится из работы) |
| `prototypes/` | старые прототипы — не трогать |

### Кабинет: модули
- `auth/` — вход по email+паролю (Argon2id), сессии в cookie, сброс пароля, роли (`participant`, `judge`, `moderator`, `admin`).
- `participation/` — участница: Игры, задания (`rules.py` — сроки, окна сдачи, статусы; `game.py` — загрузка состояния
  Игры и `notify` — колокольчик), сдача работ и фото (`media.py`: проверка, уменьшение, без EXIF), галерея (`gallery.py`),
  водяной знак FPL на чужих фото (`watermark.py`), профиль/уведомления/поддержка (`account.py`).
- `judging/` — пулы, пары, критерии, голоса, расчёт (`compute.py` — чистые функции), публикация итогов тура.
- `results/` — итоги Игры, места, TOP-10/25, очки, дипломы.
- `relay.py` — тур-эстафета. `claims.py` — заявки на вход и объединение аккаунтов. `reviews.py` — платный разбор от судьи.
- `org/` — кабинет организатора: обзор-дашборд (`home.py`), Игры и туры (`games.py`, `rounds.py`, `overview.py`),
  участницы (`participants.py`), люди (`people.py`), работы за участницу и TOP WORK вручную (`works.py`),
  перенос из бота (`bot_import.py`, `bot_photos.py`), документы, поддержка, ключи ленты.
- `messengers.py` — уведомления в Telegram и ВКонтакте: привязка одноразовым кодом, доставка того, что попало в
  колокольчик, рассылка организатора. Токены — только на сервере (env `FPL_TG_*`, `FPL_VK_*`).
- `feed.py` — лента данных для внешних инструментов (только чтение, без персональных данных, с учётом согласий).

### Фронтенд кабинета
- Ванильный JS, одна страница: `core.js` (объект `K`: `K.api`, `K.load`, `K.page`, `K.on(regex, fn)`, `K.actions.*` по `data-act`),
  `pages.js`/`account.js`/`judge.js` — участница и судья, `org*.js` — организатор (объект `O`, маршруты `O.on`).
- CSP строгий: **никаких inline-скриптов и `style="..."`**. Ширины полос — через `data-w` и классы; стили — в `cabinet.css`/`kabinet.css`
  на CSS-переменных (`--ink`, `--muted`, `--sunk`, `--line`, `--accent`, тёмная тема поддерживается).
- Каждый экран проверять на телефоне 390 px и компьютере 1280 px, без горизонтальной прокрутки.

## 4. Как работать (обязательный порядок)

1. **Ветка**: всегда отдельная ветка `codex/<коротко-о-задаче>` от свежего `main`. В `main` не пушить.
   Готово → Pull Request с описанием по-русски: что сделано, как проверено, что нужно от Светланы.
2. **Тесты кабинета** (нужен локальный PostgreSQL; тесты сами создают и удаляют базу `*_test`):
   ```sh
   cd kabinet && pip install -r requirements-dev.txt
   FPL_TEST_DSN=postgresql://USER:PASS@127.0.0.1:5432/kab_test python -m pytest -q
   FPL_SIM_DSN=…same… python -m sim.game01          # должно закончиться «PROBLEMS 0»
   ```
   Новая логика → новый тест рядом с похожими (`tests/test_*.py`). Все тесты должны проходить.
3. **Экраны**: `FPL_TEST_DSN=… python tests/demo_server.py 8200` → кабинет на http://127.0.0.1:8200
   (anna@example.com — участница, admin@example.com — администратор, пароль в `tests/conftest.py`). Скриншоты 390 и 1280 px в PR.
4. **Сайт**: правки в `src/` или `build/` → `bash build/build.sh` → `bash tests/check-build.sh` («Поломки: 0») → коммит вместе с `dist/`.
5. **Изменение базы**: только новой миграцией `server/db/schema/0NN_<что>.sql` (`BEGIN; … COMMIT;`, только добавлять —
   существующие данные не ломать) + вписать шаг в цепочку `server/db/fpl-db-setup` + поднять `SCHEMA_REQUIRED` в
   `kabinet/kabinet/main.py` + версию в `tests/test_auth.py`/`test_setup.py`. У роли кабинета в базе нет прав на DDL.
6. **Пакет сервера** (если менялись кабинет/база/скрипты): `bash server/ops/pack.sh` → `out/fpl-ops.tgz`
   (не коммитится). В PR написать «нужен пакет» — Светлана загрузит его сама после слияния.
7. Коммиты — понятные, по-русски, маленькие; не переформатировать чужой код и не переименовывать файлы без нужды.
   В том же репозитории работает Claude — перед PR подтяни свежий `main` и разреши конфликты.

## 5. Правила, которые нельзя нарушать

**Безопасность и приватность**
- Репозиторий **публичный**. Никаких ключей, токенов, паролей, адресов почты участниц, таблиц с персональными данными
  (CSV из бота и т. п.) — ни в коде, ни в тестах, ни в PR. Тест `test_no_secrets.py` должен проходить.
- Секреты живут только на сервере (`/etc/fpl-*.env`, `/var/lib/fpl/private/`, 0600). Новый секрет → закрытая страница
  `/admin/*.html` + обработчик в `server/fpl-ingest.py`, Светлана вводит его сама. Никогда не просить прислать секрет в чат.
- Публичный сайт и лента получают только то, что разрешено: без email, без полных имён, если человек скрыл имя;
  работы — только с согласием на публикацию. Любая новая выгрузка — через `site_views.sql` / `feed.py` с этими фильтрами.
- Правила лиги, п. 7.3: во время Игры публично не показывать баллы, места и общий рейтинг. Организатор видит всё.
- Не создавать администраторов, не добавлять «чёрных ходов» восстановления пароля, не ослаблять CSP/проверку Origin.

**Данные и логика**
- Опубликованные итоги туров не пересчитывать молча. Исправление — новая версия `round_results` (is_current) и запись
  в `audit_log` с причиной; действия организатора — всегда с причиной и журналом.
- Повторный запуск любой операции не должен ничего задваивать (идемпотентность: уникальные ключи, `ON CONFLICT`).
- Решения организатора важнее «красивой» логики: если правило неочевидно — спроси в PR, а не выдумывай.
- Рассылки и сообщения участницам — только по явной команде организатора.
- Нагрузка: сервер — 1 процессор и ~1 ГБ памяти, служба кабинета ограничена 350 МБ. Тяжёлые операции (фото) — с ограничением
  параллельности; запросы — без N+1 на сотни строк.

**Тексты интерфейса**
- По-русски, просто и коротко, на «вы»; кавычки «ёлочки», буква «ё»; без англицизмов и жаргона («пул», «стрим» — нельзя
  в интерфейсе участницы). Лиги — Gold/Silver/Bronze, «TOP WORK» — так и пишется. Время — «19 октября, 23:59» МСК.
